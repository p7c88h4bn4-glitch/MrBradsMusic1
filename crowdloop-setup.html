CrowdLoop — Setup Guide

CrowdLoop runs on a backend you own, so your audience's recordings stay in your account and pass through nobody else's. This is how to stand one up, start to finish, in about half an hour. No programming, and nothing to install on a computer.

1. What the two services do#

CrowdLoop is an iOS app and an AUv3 plugin, but neither can do its job alone. An audience member with a phone has to be able to reach something over the open internet, and that something cannot be your iPad. Two hosted services fill that gap, and they do different jobs.

Service A, Supabase: the audio and the records#

Holds three things:

What Where it lives
Session and submission records Postgres database
The audio files themselves Private storage bucket
Your performer login Supabase Auth

This is the part that must be a real backend rather than a static file, because it enforces the rules: who may write, who may read, when a session is open, how many sounds one session accepts. Those rules live in the database as Row Level Security, not in any app, which is what makes them impossible to bypass by editing the web page.

Service B, Netlify: the recording page#

Serves exactly one file: a single self-contained HTML page. An audience member scans the QR code, that page opens, they record three seconds, and the page uploads straight to Supabase.

Netlify is doing nothing clever here. It is a web server for one static file. Any host that can serve HTML over HTTPS works identically — Netlify is the documented path because it deploys by dragging a folder onto a web page and costs nothing at this scale.

The audience phone never talks to your device, and the two devices never need to be on the same network. Step 6 is local file I/O, which is why the plugin keeps playing when the venue wifi dies.

2. What it costs#

Both services have free tiers that comfortably cover live use.

Supabase free tier: 500 MB database, 1 GB file storage, 50,000 monthly active users. A three-second mono WAV at 48 kHz is about 290 KB, so 1 GB is roughly 3,400 recordings. A busy show might produce 100. You will run out of patience for moderation long before you run out of storage.

One free-tier catch worth knowing: a Supabase project is paused after 7 days of inactivity. It comes back with one click from the dashboard, but it does not come back on its own when a request arrives. If you go a couple of weeks between shows, open the dashboard the day before and confirm the project is awake. This is the single most likely cause of a page that will not connect at a show.

Netlify free tier: 100 GB bandwidth a month. The page is around 48 KB, so that is about two million loads.

Deleting old sessions keeps you well inside both. Section 12 has the SQL.

3. Before you start#

You need:

  • An email address you control. Both service accounts use it, and so does the CrowdLoop sign-in you create in section 4.5.
  • A password manager, or somewhere you reliably keep passwords. This setup produces three of them. Section 10 explains which is which and what happens when one goes missing.
  • A computer with a text editor. Notepad, TextEdit in plain-text mode, or anything similar. You will paste the recording page into it once and change five lines.
  • A phone with a browser, for testing. A desktop browser is not a substitute — the microphone and audio-routing behaviour that matters is mobile behaviour.
  • Your iPad, with CrowdLoop installed.

You do not need Xcode, a developer account, or any programming. Everything below is copy, paste, and filling in boxes.

Budget about 30 minutes for the first run through. Do it at a desk on an ordinary day, not in a library car park twenty minutes before a show.

4. Service A: Supabase#

4.1 Create the account and project#

  1. Go to https://supabase.com and sign up.
  2. New project.
  3. Fill in: - Name — anything. crowdloop is fine. - Database password — generate a strong one and save it in your password manager. 4.2 Run the schema#

This creates the tables, the security policies, the helper functions, and the private storage bucket, in one pass. It is idempotent — running it twice is harmless, and re-running it is the correct first move whenever the backend misbehaves.

Dashboard → SQL Editor → New query. Paste the whole block below and press Run.

Supabase may interrupt with "Potential issue detected — this query creates a table without enabling Row Level Security." Choose Run and enable RLS (the green button). The warning comes from a static check that stops reading before it reaches the part of this script that enables RLS itself; the green button is redundant with what the script already does, and harmless.

Never choose Run without RLS on this project. RLS is the entire security model.

-- ============================================================================
-- CrowdLoop Phase 2 — schema, security, storage
-- Run this once in the Supabase SQL Editor (Dashboard -> SQL Editor -> New query).
-- Safe to re-run: everything is idempotent.
-- ============================================================================

-- ---------------------------------------------------------------------------
-- SECURITY MODEL
--
-- Audience members are never authenticated. They hold only the publishable
-- key, which is public by design, so the database itself has to be the
-- boundary. Three rules follow from that:
--
--   1. anon has NO direct read on sessions. It can only call one function,
--      get_open_session(code), which returns a single open session and only
--      the fields a recording page needs. Without this, holding the
--      publishable key would let anyone enumerate every open session.
--
--   2. anon can INSERT a submission but never SELECT, UPDATE or DELETE one.
--      An audience member cannot read back their own upload, cannot see
--      anyone else's, and cannot approve anything. Moderation is the
--      performer's alone.
--
--   3. anon can write into storage but never read. Audio comes back out only
--      through a signed URL minted for the authenticated owner.
--
-- The insert policies need to check "is this session open?", but anon cannot
-- read sessions. That is what session_is_open() is for: SECURITY DEFINER, so
-- the check runs with the owner's rights while the caller stays blind.
-- ---------------------------------------------------------------------------

-- ============================================================================
-- TABLES
-- ============================================================================

create table if not exists public.sessions (
    id                      uuid primary key default gen_random_uuid(),
    owner_id                uuid not null references auth.users(id) on delete cascade,
    title                   text not null,
    prompt                  text not null default '',
    status                  text not null default 'draft',
    -- Short code carried by the QR image. Also typeable by hand, which
    -- matters when a phone camera will not focus in a dark room.
    public_code             text not null unique,
    max_duration_seconds    integer not null default 3,
    -- Abuse ceiling per session. Cheap, and it bounds a flood without
    -- needing per-IP tracking.
    max_submissions         integer not null default 300,
    created_at              timestamptz not null default now(),
    closes_at               timestamptz,

    constraint sessions_status_valid
        check (status in ('draft', 'open', 'closed')),
    constraint sessions_duration_sane
        check (max_duration_seconds between 1 and 10),
    constraint sessions_code_shape
        check (public_code ~ '^[A-Z0-9]{4,12}$')
);

create table if not exists public.submissions (
    id              uuid primary key default gen_random_uuid(),
    session_id      uuid not null references public.sessions(id) on delete cascade,
    status          text not null default 'pending',
    label           text not null default '',
    duration        real not null default 0,
    -- Path inside the private 'submissions' bucket: <session_id>/<id>.wav
    storage_path    text,
    mime_type       text,
    file_size       integer,
    -- 0..15, or null when approved but not yet placed on a pad.
    assigned_pad    integer,
    created_at      timestamptz not null default now(),

    constraint submissions_status_valid
        check (status in ('pending', 'approved', 'rejected')),
    constraint submissions_pad_range
        check (assigned_pad is null or assigned_pad between 0 and 15),
    constraint submissions_duration_sane
        check (duration >= 0 and duration <= 10)
);

-- One sound per pad per session.
create unique index if not exists submissions_one_per_pad
    on public.submissions (session_id, assigned_pad)
    where assigned_pad is not null;

create index if not exists submissions_by_session
    on public.submissions (session_id, created_at desc);

create index if not exists sessions_by_owner
    on public.sessions (owner_id, created_at desc);

-- ============================================================================
-- HELPERS
-- ============================================================================

-- Ambiguity-free alphabet: no O/0, no I/1, no S/5. A code read aloud from a
-- stage, or squinted at from the back of a room, should not need a retry.
create or replace function public.generate_session_code()
returns text
language plpgsql
as $$
declare
    alphabet constant text := 'ABCDEFGHJKLMNPQRTUVWXYZ23456789';
    candidate text;
    attempt integer := 0;
begin
    loop
        candidate := '';
        for i in 1..6 loop
            candidate := candidate ||
                substr(alphabet, 1 + floor(random() * length(alphabet))::int, 1);
        end loop;

        exit when not exists (
            select 1 from public.sessions where public_code = candidate
        );

        attempt := attempt + 1;
        if attempt > 50 then
            raise exception 'Could not allocate a unique session code';
        end if;
    end loop;

    return candidate;
end;
$$;

-- SECURITY DEFINER so RLS policies can ask this question on behalf of a
-- caller that has no read access to sessions at all.
create or replace function public.session_is_open(target uuid)
returns boolean
language sql
security definer
set search_path = public
stable
as $$
    select exists (
        select 1
        from public.sessions
        where id = target
          and status = 'open'
          and (closes_at is null or closes_at > now())
    );
$$;

-- The only window anon has onto sessions. Takes a code, returns at most one
-- row, and never exposes owner_id or anything else internal.
create or replace function public.get_open_session(code text)
returns table (
    id uuid,
    title text,
    prompt text,
    max_duration_seconds integer
)
language sql
security definer
set search_path = public
stable
as $$
    select s.id, s.title, s.prompt, s.max_duration_seconds
    from public.sessions s
    where s.public_code = upper(trim(code))
      and s.status = 'open'
      and (s.closes_at is null or s.closes_at > now())
    limit 1;
$$;

-- Enforces the per-session ceiling at write time.
create or replace function public.enforce_submission_cap()
returns trigger
language plpgsql
security definer
set search_path = public
as $$
declare
    ceiling integer;
    current_total integer;
begin
    select max_submissions into ceiling
    from public.sessions
    where id = new.session_id;

    select count(*) into current_total
    from public.submissions
    where session_id = new.session_id;

    if current_total >= coalesce(ceiling, 300) then
        raise exception 'This session has reached its submission limit'
            using errcode = 'check_violation';
    end if;

    return new;
end;
$$;

drop trigger if exists submissions_cap on public.submissions;
create trigger submissions_cap
    before insert on public.submissions
    for each row execute function public.enforce_submission_cap();

-- ============================================================================
-- ROW LEVEL SECURITY
-- ============================================================================

alter table public.sessions    enable row level security;
alter table public.submissions enable row level security;

-- --- sessions: owner only, in every direction ---

drop policy if exists "owner reads own sessions" on public.sessions;
create policy "owner reads own sessions"
    on public.sessions for select
    to authenticated
    using (owner_id = auth.uid());

drop policy if exists "owner creates own sessions" on public.sessions;
create policy "owner creates own sessions"
    on public.sessions for insert
    to authenticated
    with check (owner_id = auth.uid());

drop policy if exists "owner updates own sessions" on public.sessions;
create policy "owner updates own sessions"
    on public.sessions for update
    to authenticated
    using (owner_id = auth.uid())
    with check (owner_id = auth.uid());

drop policy if exists "owner deletes own sessions" on public.sessions;
create policy "owner deletes own sessions"
    on public.sessions for delete
    to authenticated
    using (owner_id = auth.uid());

-- Note: no anon policy on sessions at all. get_open_session() is the door.

-- --- submissions: anon writes, owner reads and moderates ---

drop policy if exists "anon submits to open sessions" on public.submissions;
create policy "anon submits to open sessions"
    on public.submissions for insert
    to anon
    with check (
        public.session_is_open(session_id)
        -- An audience member cannot pre-approve their own sound or park it
        -- straight onto a pad.
        and status = 'pending'
        and assigned_pad is null
    );

-- A signed-in performer submitting into their own session, e.g. testing.
drop policy if exists "owner submits to own sessions" on public.submissions;
create policy "owner submits to own sessions"
    on public.submissions for insert
    to authenticated
    with check (
        exists (
            select 1 from public.sessions s
            where s.id = session_id and s.owner_id = auth.uid()
        )
    );

drop policy if exists "owner reads own submissions" on public.submissions;
create policy "owner reads own submissions"
    on public.submissions for select
    to authenticated
    using (
        exists (
            select 1 from public.sessions s
            where s.id = session_id and s.owner_id = auth.uid()
        )
    );

drop policy if exists "owner moderates own submissions" on public.submissions;
create policy "owner moderates own submissions"
    on public.submissions for update
    to authenticated
    using (
        exists (
            select 1 from public.sessions s
            where s.id = session_id and s.owner_id = auth.uid()
        )
    )
    with check (
        exists (
            select 1 from public.sessions s
            where s.id = session_id and s.owner_id = auth.uid()
        )
    );

drop policy if exists "owner deletes own submissions" on public.submissions;
create policy "owner deletes own submissions"
    on public.submissions for delete
    to authenticated
    using (
        exists (
            select 1 from public.sessions s
            where s.id = session_id and s.owner_id = auth.uid()
        )
    );

-- ============================================================================
-- STORAGE
-- ============================================================================

-- Private bucket. 'public' false means no URL works without a signature.
insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values (
    'submissions',
    'submissions',
    false,
    2097152,                        -- 2 MB ceiling; a 3 s mono WAV is ~290 KB
    array['audio/wav', 'audio/x-wav', 'audio/wave']
)
on conflict (id) do update
set public = false,
    file_size_limit = 2097152,
    allowed_mime_types = array['audio/wav', 'audio/x-wav', 'audio/wave'];

drop policy if exists "anon uploads to open sessions" on storage.objects;
create policy "anon uploads to open sessions"
    on storage.objects for insert
    to anon
    with check (
        bucket_id = 'submissions'
        -- First path segment is the session id: <session_id>/<submission_id>.wav
        and public.session_is_open(((storage.foldername(name))[1])::uuid)
    );

drop policy if exists "owner reads own session audio" on storage.objects;
create policy "owner reads own session audio"
    on storage.objects for select
    to authenticated
    using (
        bucket_id = 'submissions'
        and exists (
            select 1 from public.sessions s
            where s.id = ((storage.foldername(name))[1])::uuid
              and s.owner_id = auth.uid()
        )
    );

drop policy if exists "owner deletes own session audio" on storage.objects;
create policy "owner deletes own session audio"
    on storage.objects for delete
    to authenticated
    using (
        bucket_id = 'submissions'
        and exists (
            select 1 from public.sessions s
            where s.id = ((storage.foldername(name))[1])::uuid
              and s.owner_id = auth.uid()
        )
    );

-- ============================================================================
-- GRANTS
-- ============================================================================

grant usage on schema public to anon, authenticated;

grant select, insert, update, delete on public.sessions    to authenticated;
grant select, insert, update, delete on public.submissions to authenticated;
grant insert                          on public.submissions to anon;

grant execute on function public.get_open_session(text)  to anon, authenticated;
grant execute on function public.session_is_open(uuid)   to anon, authenticated;
grant execute on function public.generate_session_code() to authenticated;

-- anon deliberately gets nothing on sessions.
revoke all on public.sessions from anon;

4.3 Add the column defaults#

Run this as a separate query, after the schema.

Without it the iOS app cannot create a session. It would have to invent a public_code itself, and it cannot check that code is unique — RLS lets a performer see only their own sessions, so the client has no way to know whether a code is already taken. Generating it inside the database is the only place that check is possible.

-- ============================================================================
-- CrowdLoop — column defaults so the iOS app can create sessions
--
-- Run this once, after 01_schema.sql.
--
-- Without these the app would have to invent a public_code itself, and it
-- cannot: RLS lets a performer see only their own sessions, so the client has
-- no way to check a code is globally unique. Generating it in the database is
-- the only place that check is possible.
-- ============================================================================

alter table public.sessions
    alter column public_code set default public.generate_session_code();

alter table public.sessions
    alter column owner_id set default auth.uid();

-- Confirm
select
    column_name,
    column_default
from information_schema.columns
where table_schema = 'public'
  and table_name = 'sessions'
  and column_name in ('public_code', 'owner_id')
order by column_name;

You should get two rows back, showing public_code and owner_id now have defaults.

4.4 Verify#

New query. Every row must say PASS.

-- ============================================================================
-- CrowdLoop Phase 2 — verification
-- Run AFTER 01_schema.sql. Each block should print PASS.
-- ============================================================================

-- 1. Tables exist with RLS on
select
    case when count(*) = 2 then 'PASS: both tables exist with RLS enabled'
         else 'FAIL: expected 2 RLS-enabled tables, found ' || count(*)
    end as result
from pg_tables
where schemaname = 'public'
  and tablename in ('sessions', 'submissions')
  and rowsecurity = true;

-- 2. anon has no read path into sessions
select
    case when count(*) = 0 then 'PASS: anon has no policy on sessions'
         else 'FAIL: anon can reach sessions directly through ' || count(*) || ' policy'
    end as result
from pg_policies
where schemaname = 'public'
  and tablename = 'sessions'
  and 'anon' = any(roles);

-- 3. anon can insert submissions but nothing else
select
    case when count(*) filter (where cmd = 'INSERT') = 1
          and count(*) filter (where cmd <> 'INSERT') = 0
         then 'PASS: anon on submissions is insert-only'
         else 'FAIL: anon has unexpected access to submissions'
    end as result
from pg_policies
where schemaname = 'public'
  and tablename = 'submissions'
  and 'anon' = any(roles);

-- 4. Bucket is private
select
    case when not public then 'PASS: submissions bucket is private'
         else 'FAIL: submissions bucket is PUBLIC — audio is world-readable'
    end as result
from storage.buckets
where id = 'submissions';

-- 5. anon can write to storage but not read it
select
    case when count(*) filter (where cmd = 'INSERT') >= 1
          and count(*) filter (where cmd = 'SELECT') = 0
         then 'PASS: anon can upload but not download'
         else 'FAIL: check anon storage policies'
    end as result
from pg_policies
where schemaname = 'storage'
  and tablename = 'objects'
  and 'anon' = any(roles);

-- 6. Helper functions are SECURITY DEFINER
select
    case when count(*) = 2 then 'PASS: helper functions are SECURITY DEFINER'
         else 'FAIL: expected 2 definer functions, found ' || count(*)
    end as result
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and p.proname in ('get_open_session', 'session_is_open')
  and p.prosecdef = true;

-- 7. Code generator produces a valid code
select
    case when public.generate_session_code() ~ '^[A-Z0-9]{6}$'
         then 'PASS: session codes generate correctly'
         else 'FAIL: generate_session_code() returned an unexpected shape'
    end as result;

If any row says FAIL, stop. A FAIL here means the security model is wrong, and that matters more than anything else in this setup. Re-run section 4.2 in full and verify again.

4.5 Create your performer account#

Dashboard → Authentication → Users → Add user → Create new user.

Use a real email and a password you will keep. Tick Auto Confirm User so you are not waiting on a confirmation email.

This is the account the iOS app signs in as. Audience members never get an account, never sign in, and never see anything that requires one.

Put this password in your password manager now. It is not the same as the database password from section 4.1, and it is not your supabase.com login. Section 10 covers all three, how to change this one from inside the app, and what to do when it is gone.

4.6 Collect your two values#

Dashboard → Project Settings (the gear) → API.

Copy these two, and keep them somewhere you can paste from:

Value Looks like Where it goes
Project URL https://abcdefghijklm.supabase.co the recording page (section 5.2) and the app (section 6)
Publishable key (also labelled anon / public) sb_publishable_… or a long eyJ… JWT the same two places

Email them to yourself, or put them in a note you can paste from on both the computer and the iPad. You will type each one twice.

The publishable key is meant to be public. It ships inside the app binary and inside the web page, where anyone can read it. It grants nothing on its own — every restriction is enforced by Row Level Security on the server, so a copy of this key lets an attacker do exactly what an audience member can do: insert a pending submission into a session that is currently open. Nothing else.

The service_role key on that same page is the opposite. It bypasses RLS entirely. Never put it in the app, the web page, a git repository, or anything you paste into an AI tool. You do not need it for anything in this guide.

  function resampleToMono(buffer, maxSeconds) {

    source.connect(offline.destination);
    source.start(0, 0, seconds);

    var rendered = offline.startRendering();
    if (rendered && typeof rendered.then === "function") {
      return rendered;
    }
    return new Promise(function (resolve) {
      offline.oncomplete = function (event) { resolve(event.renderedBuffer); };
    });
  }

  function encodeWav(audioBuffer) {
    var samples = audioBuffer.getChannelData(0);
    var frameCount = samples.length;
    var bytesPerSample = 2;
    var dataBytes = frameCount * bytesPerSample;
    var buffer = new ArrayBuffer(44 + dataBytes);
    var view = new DataView(buffer);

    function writeString(offset, text) {
      for (var i = 0; i < text.length; i++) {
        view.setUint8(offset + i, text.charCodeAt(i));
      }
    }

    writeString(0, "RIFF");
    view.setUint32(4, 36 + dataBytes, true);
    writeString(8, "WAVE");
    writeString(12, "fmt ");
    view.setUint32(16, 16, true);                       // PCM chunk size
    view.setUint16(20, 1, true);                        // format = PCM
    view.setUint16(22, 1, true);                        // channels = mono
    view.setUint32(24, TARGET_SAMPLE_RATE, true);
    view.setUint32(28, TARGET_SAMPLE_RATE * bytesPerSample, true);
    view.setUint16(32, bytesPerSample, true);           // block align
    view.setUint16(34, 16, true);                       // bits per sample
    writeString(36, "data");
    view.setUint32(40, dataBytes, true);

    // Find the loudest point so quiet recordings are not inaudible over a PA.
    // Capped so a near-silent take is not amplified into pure noise.
    var peak = 0;
    for (var p = 0; p < frameCount; p++) {
      var magnitude = samples[p] < 0 ? -samples[p] : samples[p];
      if (magnitude > peak) { peak = magnitude; }
    }
    var gain = 1;
    if (peak > 0.0001) {
      gain = Math.min(0.89 / peak, 8);
    }

    var offset = 44;
    for (var i = 0; i < frameCount; i++) {
      var value = samples[i] * gain;
      if (value > 1) { value = 1; } else if (value < -1) { value = -1; }
      view.setInt16(offset, Math.round(value * 32767), true);
      offset += 2;
    }

    return new Blob([buffer], { type: "audio/wav" });
  }

  function convertRecording(blob, maxSeconds) {
    var context = null;
    return decodeToBuffer(blob).then(function (result) {
      context = result.ctx;
      return resampleToMono(result.buffer, maxSeconds);
    }).then(function (rendered) {
      if (context && typeof context.close === "function") { context.close(); }
      return {
        wav: encodeWav(rendered),
        seconds: rendered.length / TARGET_SAMPLE_RATE
      };
    }).catch(function (error) {
      if (context && typeof context.close === "function") { context.close(); }
      throw error;
    });
  }

  function pickMimeType() {
    if (typeof MediaRecorder === "undefined" ||
        typeof MediaRecorder.isTypeSupported !== "function") {
      return "";
    }
    var candidates = [
      "audio/webm;codecs=opus",
      "audio/webm",
      "audio/mp4",
      "audio/aac",
      "audio/ogg;codecs=opus"
    ];
    for (var i = 0; i < candidates.length; i++) {
      if (MediaRecorder.isTypeSupported(candidates[i])) { return candidates[i]; }
    }
    return "";
  }

  function startLevelMeter(stream) {
    try {
      var ctx = unlockAudio();
      if (!ctx) { return; }
      meterSource = ctx.createMediaStreamSource(stream);
      analyser = ctx.createAnalyser();
      analyser.fftSize = 512;
      meterSource.connect(analyser);

      var data = new Uint8Array(analyser.frequencyBinCount);
      var fill = $("meter-fill");

      var draw = function () {
        analyser.getByteTimeDomainData(data);
        var peak = 0;
        for (var i = 0; i < data.length; i++) {
          var deviation = Math.abs(data[i] - 128);
          if (deviation > peak) { peak = deviation; }
        }
        fill.style.width = Math.min(100, (peak / 128) * 140) + "%";
        levelRaf = requestAnimationFrame(draw);
      };
      draw();
    } catch (e) {
      // A missing level meter is cosmetic; recording still works.
    }
  }

      meterSource = null;
    }
    if (analyser) {
      try { analyser.disconnect(); } catch (e) { /* already gone */ }
      analyser = null;

    // sharedCtx is intentionally left open and unlocked for playback.
  }

  // Same context and same output as playBack, but nothing is decoded. If this
  // is audible and the recording is not, the problem is the audio data. If
  // neither is audible, the problem is the context or the output route.
  function playTestTone() {
    clearTrace();
    setAudioSession("playback");
    var ctx = unlockAudio();
    trace("tone: " + describeCtx(ctx));
    trace("tone: " + describeSession());

    if (!ctx) {
      trace("tone: FAILED, no Web Audio on this browser");
      return;
    }

    try {
      var osc = ctx.createOscillator();
      var gain = ctx.createGain();
      osc.frequency.value = 440;
      gain.gain.value = 0.2;
      osc.connect(gain);
      gain.connect(ctx.destination);
      osc.start();
      osc.stop(ctx.currentTime + 0.6);
      trace("tone: started 440Hz for 0.6s");
      osc.onended = function () { trace("tone: finished, state=" + ctx.state); };
    } catch (error) {
      trace("tone: THREW " + (error.message || error));
    }
  }

  function playBack() {
    clearTrace();

    if (!recordedWav) {
      trace("play: nothing recorded yet");
      return;
    }
    trace("play: blob " + recordedWav.size + " bytes, type " + (recordedWav.type || "(none)"));

    stopPlayback();
    setAudioSession("playback");
    var ctx = unlockAudio();
    trace("play: " + describeCtx(ctx));
    trace("play: " + describeSession());

    if (!ctx) {
      trace("play: no Web Audio, using <audio> fallback");
      playBackFallback();
      return;
    }

    recordedWav.arrayBuffer().then(function (data) {
      trace("play: read " + data.byteLength + " bytes");
      return new Promise(function (resolve, reject) {
        var maybe = ctx.decodeAudioData(data, resolve, reject);
        if (maybe && typeof maybe.then === "function") {
          maybe.then(resolve).catch(reject);
        }
      });
    }).then(function (buffer) {
      trace("play: decoded " + buffer.duration.toFixed(2) + "s, " +
            buffer.numberOfChannels + "ch @ " + buffer.sampleRate + "Hz");

      var source = ctx.createBufferSource();
      source.buffer = buffer;
      source.connect(ctx.destination);
      source.onended = function () {
        playbackSource = null;
        trace("play: finished");
      };
      source.start(0);
      playbackSource = source;

      trace("play: started, ctx state=" + ctx.state);
      if (ctx.state !== "running") {
        trace("play: context is NOT running — no sound will come out");
      }
    }).catch(function (error) {
      trace("play: FAILED " + (error && error.message ? error.message : error));
      trace("play: trying <audio> fallback");
      if (window.console) { console.error(error); }
      playBackFallback();
    });
  }

  // Only reached if Web Audio is unavailable or the decode fails.
  function playBackFallback() {
    if (!recordedWav) { return; }
    if (previewUrl) { URL.revokeObjectURL(previewUrl); }
    previewUrl = URL.createObjectURL(recordedWav);
    previewAudio = new Audio(previewUrl);
    previewAudio.setAttribute("playsinline", "");
    previewAudio.playsInline = true;

    previewAudio.onerror = function () {
      trace("fallback: <audio> could not load the blob");
    };
    previewAudio.onplaying = function () {
      trace("fallback: <audio> is playing");
    };

    previewAudio.play().then(function () {
      trace("fallback: play() resolved");
    }).catch(function (error) {
      trace("fallback: play() rejected — " + (error && error.name ? error.name : error));
      setStatus("review-status",
        "Could not play it back here. You can still send it.", "error");
    });
  }

8. Proving the security holds#

Worth doing once, because this is the part that protects your audience. Each check should fail to return data.

Closed sessions reject uploads. In Table Editor, set your session's status to closed. Reload the recording page and try to send. It should be refused. Set it back to open.

The publishable key does not leak your sessions. Paste this into a browser, substituting your own project URL and key:

https://YOUR-PROJECT.supabase.co/rest/v1/sessions?apikey=YOUR-PUBLISHABLE-KEY

Expected: an empty array [] or a permission error. Not a list of your sessions. If you can see your sessions there, RLS is not working — re-run section 4.2 and re-verify before using this at an event.

Audio is not world-readable. In Storage, click an uploaded .wav, copy its URL, and open it in a private browsing window. It must be denied. Audio comes out only through a short-lived signed URL minted for your signed-in account.

Submissions cannot be read back. Same idea as the sessions check:

https://YOUR-PROJECT.supabase.co/rest/v1/submissions?apikey=YOUR-PUBLISHABLE-KEY

Expected: empty or denied. An audience member cannot read back even their own upload, let alone anyone else's.

What the model actually guarantees#

  • An audience member can insert a submission into a session that is currently open. That is the whole of their access.
  • They cannot list sessions, read submissions, download audio, approve anything, or assign a pad. The insert policy explicitly refuses a row that arrives pre-approved or already pointed at a pad.
  • Nothing plays anywhere until you approve it by hand. There is no code path that moves a sound onto a pad without a moderation action.
  • Per-session caps (300 submissions, 2 MB per file) are enforced by a database trigger and a bucket setting, not by the web page, so editing the HTML cannot raise them.

9. Running a session#

Keep exactly one session open at a time. This is the single most common self-inflicted problem. Two open sessions means submissions silently land in whichever one the audience member's link pointed at, while you watch the other one stay empty. Nothing errors. To close everything but the newest:

update public.sessions set status = 'closed' where status = 'open';

The code and the link are interchangeable. The QR encodes https://your-site/crowdloop/?c=CODE, which skips the code entry screen. The same six characters can also be typed by hand, which matters when a phone camera will not focus in a dark room.

Codes avoid ambiguous characters. The alphabet excludes O/0, I/1 and S/5, so a code survives being read aloud from a stage.

Closing a session is instant. New uploads are refused from the moment status changes. Already-approved sounds keep working on your pads — closing affects intake, not playback.

Audio format is fixed at the door. The page decodes whatever the phone recorded (WebM/Opus on Android, MP4/AAC on iOS) and re-encodes to 16-bit mono WAV at 48 kHz before uploading. The bucket only accepts audio/wav, so this is enforced server-side too. One format reaches the sampler regardless of phone.

Levels are normalised. Each recording is peak-normalised to about −1 dBFS, capped at 8× gain, so a quiet phone at the back of a room still comes through a PA while a near-silent take is not amplified into hiss.

Diagnostics are one URL parameter away. Add &debug=1 to the recording page URL to reveal a test-tone button and a stage-by-stage trace of the audio pipeline. Without it the page stays clean for the audience. Every trace line also goes to console.log prefixed [crowdloop] regardless.

11. Troubleshooting#

"Could not connect" / the page spins forever#

In order of likelihood:

  1. The Supabase project is paused. Free-tier projects pause after 7 days idle. Open the dashboard and resume it. This is the most common cause after a gap between shows.
  2. The credentials in the page are wrong. Check the YOUR DETAILS block in the deployed file against section 4.6.
  3. The schema is missing. Run section 12's diagnostic.
  4. You are looking at a cached copy. See below.

Add &debug=1 to the URL — the page will name the actual failure instead of a generic message.

"No open session with that code"#

The connection is fine; the lookup returned nothing. Either the code is wrong, or that session is closed. Check:

select public_code, status, title from public.sessions order by created_at desc;

The page looks old after deploying#

Both Netlify and mobile Safari cache aggressively, and you can spend a long time debugging a file that is not the one you deployed. On iPhone: Settings → Safari → Clear History and Website Data, then reload. A private window also bypasses the cache and is faster for a quick check.

"Multiple commands produce…" in Xcode#

Two targets are writing the same build artifact. Check that the app target and the AUv3 extension target have different Product Names. Product Name is the filename of the built artifact; it is not what Loopy displays. The display name lives in the extension's Info tab under NSExtension → NSExtensionAttributes → AudioComponents → Item 0 → name.

Playback works on desktop but not on iPhone#

Almost always the iOS audio session. Once a page uses the microphone, iOS routes output to the earpiece receiver and the ring/silent switch mutes it — with no error, and with the audio pipeline reporting complete success. The page already handles this by declaring navigator.audioSession.type = "playback" before making sound. If you have modified the page and playback goes silent, that declaration is the first thing to check.

Direct deletion from storage tables is not allowed#

Supabase blocks delete from storage.objects in SQL (error 42501). Delete audio through the dashboard instead: Storage → submissions → select folders → Delete. Do that before deleting the database rows, or you lose the folder names that tell you what to delete.

A submission uploaded but never appeared in the app#

The uploader's confirmation screen only shows after both the file upload and the row insert have succeeded, so the submission almost certainly exists. Check which session it landed in:

select
    sub.created_at,
    s.public_code as landed_in_code,
    sub.status,
    round(sub.duration::numeric, 2) as seconds
from public.submissions sub
join public.sessions s on s.id = sub.session_id
order by sub.created_at desc
limit 10;

If the code is not the one your app has selected, you had two sessions open.

12. Maintenance SQL#

Diagnose a backend that is misbehaving#

Run the whole block. Each part answers one question.

-- ============================================================================
-- CrowdLoop — what state is the backend actually in?
-- Run this whole file in the SQL Editor. Four answers come back.
-- ============================================================================

-- 1. Does the lookup function the uploader calls still exist?
select
    case when count(*) = 1
         then 'PASS: get_open_session exists'
         else 'FAIL: get_open_session is MISSING — re-run 01_schema.sql'
    end as check_1_function
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public' and p.proname = 'get_open_session';

-- 2. Can anon execute it? Without this the call returns 403.
select
    case when has_function_privilege('anon', p.oid, 'execute')
         then 'PASS: anon may call get_open_session'
         else 'FAIL: anon cannot execute it — re-run the GRANTS section'
    end as check_2_grant
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public' and p.proname = 'get_open_session';

-- 3. What sessions exist, and is any of them actually open?
select
    public_code as code,
    status,
    title,
    closes_at,
    case
        when status <> 'open' then 'NOT OPEN — the uploader will reject this code'
        when closes_at is not null and closes_at <= now() then 'EXPIRED'
        else 'USABLE — type this code into the uploader'
    end as verdict
from public.sessions
order by created_at desc;

-- 4. Does the function actually return a row for your newest open session?
--    This is the exact call the web page makes.
select
    coalesce(
        (select 'PASS: lookup returned "' || title || '"'
         from public.get_open_session(
             (select public_code from public.sessions
              where status = 'open' order by created_at desc limit 1)
         )),
        'FAIL: no open session for the function to return'
    ) as check_4_end_to_end;

Cap the submission title length#

The optional title on the recording page is free text typed by a stranger. The browser's maxlength is a convenience, not a control — anyone can post to the API directly. Run this once.

-- ============================================================================
-- CrowdLoop — bound the submission title
--
-- The 'label' column already exists, so the uploader's optional title needs no
-- new column. It does need a length limit: the field is free text typed by an
-- anonymous stranger, and the browser's maxlength is a convenience, not a
-- control — anyone can post to the API directly.
-- ============================================================================

-- Trim anything already over the limit so the constraint can be added.
update public.submissions
set label = left(label, 60)
where char_length(label) > 60;

alter table public.submissions
    drop constraint if exists submissions_label_length;

alter table public.submissions
    add constraint submissions_label_length
    check (char_length(label) <= 60);

select
    case when count(*) = 1
         then 'PASS: label is capped at 60 characters'
         else 'FAIL: constraint not applied'
    end as result
from pg_constraint
where conname = 'submissions_label_length';

13. Using something other than Supabase or Netlify#

Supabase and Netlify are the documented path, not a requirement. What CrowdLoop actually depends on is narrower than either product.

From the database service it needs:

  • A way to authenticate one performer account and hand back a bearer token.
  • Two tables reachable over HTTPS with select/insert/update/delete, filtered per-user on the server.
  • A private file store with signed, expiring download URLs.
  • The ability to let an unauthenticated caller insert a row and upload a file without being able to read anything back.

That last point is the one that is hard to replace casually. It is why the schema uses SECURITY DEFINER functions: the insert policy needs to ask "is this session open?" on behalf of a caller who has no permission to read sessions at all. Any substitute needs an equivalent mechanism, or the whole security model collapses into "trust the client".

The app talks to Supabase through App/SupabaseClient.swift, a hand-rolled URLSession client with no SDK dependency. It uses three REST surfaces — /auth/v1, /rest/v1 (PostgREST), and /storage/v1. Pointing it somewhere else means reimplementing those three against the new service, in that one file. The rest of the app does not know where the data comes from.

From the web host it needs: the ability to serve one static HTML file over HTTPS. That is genuinely all. GitHub Pages, Cloudflare Pages, Vercel, or a folder on any web server you already own will do it. Two constraints only:

  • HTTPS is mandatory. Browsers refuse microphone access on plain HTTP.
  • The file must be served as-is, not through a build step that minifies or transforms it.
